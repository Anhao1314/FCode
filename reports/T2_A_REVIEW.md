# T2-A 一次独立审查记录

两名真实原生只读子代理与 Root 并行工作，首轮只检查相关基线；主实现完成后各进行一次定向复审。无代理编辑、测试、真实 API 或凭证访问；Root 唯一实现和实验执行者。

## benchmark-methodology-reviewer

确认原 M4 不能承载新动作；要求独立任务环境、提前冻结可接受行动集合、相同观察与预算、反事实同分区、失败结果与真实金融事实分开。

定向审查认为手写 Gold 与策略实现分离、反事实只变一个可见条件、策略准确率没有 PASS 阈值。提出必须保留的研究问题：

1. 预注册 H4 宣称能消除模板重叠，实际全部使用同一 JSON Observation 模板。该部分假设不成立；原文本和指纹不改，报告标记不足。
2. c0 的 `read.supplement` 会获得正确单位的补充报表，也是合理路径；冻结 Gold 却只接受 normalize.units。没有提前定义成本/最优性准则，当前集合过窄。Root 加入可运行反例，保留其被低估的评分，不改 Gold。
3. 候选复用环境 diagnose，启发式独立复述规则；这是人工环境感知策略比较，不能宣称独立算法泛化。
4. 全部任务含数值事实，T1 对照退化成固定计算，其空证据分支未测。
5. 12 个任务只有 6 个配对机制家族，eval 只有两个家族；train 两个完整性控制语义等价。

因此 12/12 只是在当前有限标签上规则足够，不是真实研究最优性、完整接受集合或泛化上界。

## runtime-integrity-reviewer

确认直接扩展原 M2 toolGrant 会触碰冻结合同；支持独立的一次决策执行层复用原签名存储与 ModelBudgets。定向审查未发现自动重发或越权动作执行路径。

发现一个 P2：策略输入使用主机过滤权限，结果与收据复算却使用 corpus 权限，使 `maxReads=0` 的安全停止结果仍写 `remainingReads=1`、`resolvingReadAvailable=true`。Root 新增针对性负例，在 `run-xo2j4B` 真实失败（1 ≠ 0）；失败签名结果、TAP 和当时源码保留。修复把 gate、execute 与 receipt 复算统一为同一绑定主机投影；诊断 / 策略 / Gold 没改。修复后的相关 3 项为 3/3。

另加强跨任务读取额度耗尽的拒绝：新的 task 身份不能重置同一根目录的 read grant；不执行第二次工具、不新增读取预留，结果保守阻断。

Root 首轮新增测试另有两个测试实现错误：泄漏扫描误把 Object.freeze 当成标签访问；历史篡改测试用了旧 sequence，先被正确的 CAS 拒绝，未触达目标断言。分别修正检查语义和构造合法 next-sequence 的自洽伪造结果，历史不可改断言保持原样。原 R0/T1 测试均未更改。首轮 12/14 原样保留。
