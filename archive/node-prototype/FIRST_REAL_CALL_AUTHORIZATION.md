# 首次真实 DeepSeek 调用：独立授权准备清单

本轮没有授予或执行真实调用。此清单是下一阶段的前置条件，不能由本轮的注入测试批准代替。

1. 人工明确授权一次真实实验的研究对象、允许发送的数据范围、模型 `deepseek-flash`、固定 endpoint、非流式/关闭 thinking、最多调用次数、Token/费用上限、并发、停止条件及取消/未知结果处理。不要上传本地 ACL、私有财务数据、凭证或原实验状态。
2. 主机独立复核 [DeepSeek 当前价格](https://api-docs.deepseek.com/quick_start/pricing/)、币种、缓存计费规则、账户额度和模型可用性，记录来源、时间、价格快照及复核摘要。不要使用测试的人工价格。
3. 必须明确解决或接受尚未证明的输入 Token 和外部计费风险。严格要求可证明硬成本上限而又无法取得供应商保证时，继续阻断。本代码中的显式接受字段不是保证。
4. 建立可信主机 authorizer，以不可扩大 grant 绑定 principal、工具、route、调用数、每次输入/输出和总额度。静态 Harness 与 Loop 使用同一持久预算目录及 hostScope；账户跨 root 的限额另作统筹。确认当前授权撤销渠道有效。
5. 在任务外独立保管模型凭证，提供按 credentialRef 延迟解析的可信 resolver。不要将 Key 放入仓库、任务参数、Plan、环境转储、测试夹具、收据、日志或聊天。本轮不创建或读取该凭证。
6. 显式选择 live 并实现逐调用审批回调。返回当前 intent 和 authorization/config/pricing/prompt 精确绑定、短时有效的 `flowcredit.deepseek-transmission/m3-a-v1` 批准；每次复核仍须有效。不要把合成批准辅助函数用于真实主机。
7. 使用独立实验存储和可信 witness，限制本地状态访问；调用前检查尚无 unknown/held 冲突。安排供应商 request id 和账单的人工复核程序。未知结果不得自动重试，供应商报表不是本地可信 Plan 收据；没有匹配签名收据就继续阻断。
8. 首次只执行获批的最小任务，并检查真实模型、usage、Plan、只读工具结果、收据和实际账单。任何异常立即停止，保留原证据，不切模型、不退未知预留、不扩样。

仍需真实验证：公网/TLS/供应商服务行为、取消是否终止服务端计算、Token/价格与实际账单、模型标识及稳定性、真实 JSON 输出质量和研究价值。进程 SIGKILL 不能替代断电或外部计费一致性证明。
