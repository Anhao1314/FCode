# 真实数据试点协议 P0

状态：**未授权执行。** 本文件是待批准的协议，不是执行记录。文中所有数字都是待填参数或明确标注的示例，不是已获得的测量结果。

本协议只回答一个问题，并且只用一个问题决定是否继续：

> **在真实披露上，把确定性规则推到顶之后，剩下多少真有成本的残差？把这些残差交给模型，单位成本是多少？**

它不回答「模型是否比规则强」。那需要更大样本和独立复现，属于本协议之后的阶段。

---

## 0. 边界声明

| 本协议会产出 | 本协议不会产出 |
| --- | --- |
| 真实披露上的规则失败率、失败类型分布、consequential 残差率 | 模型优于规则的结论 |
| 每个残差条目的真实模型调用成本（含 unknown 的真实失败） | 训练数据、Student、蒸馏产物 |
| 由事后披露机械生成的标签及其强度分级 | 任何投资、信贷、审计意见 |
| 一份可复现的语料与标签冻结清单（只含哈希与元数据） | 原始披露正文进 Git |

三条贯穿全程的原则：

1. **合成语料只用于单元测试与回归**，不用于证明研究价值。本轮所有统计量必须来自真实披露。
2. **时间是考官**。标签由未来披露机械生成，不靠人工演双盲，不靠模型自评。
3. **规则先跑到顶**。模型只在「规则无法决策或决策被事后披露证伪」且「该失败有真实成本」的交集上被调用。

## 1. 数据范围

### 1.1 为什么选 SEC EDGAR

| 候选源 | 使用权 | 版本/重述关系 | 机械可判性 | 结论 |
| --- | --- | --- | --- | --- |
| **SEC EDGAR** | 美国联邦政府作品，属公有领域；EDGAR 提供 `data.sec.gov` 结构化接口与 `Archives` 原始文件，要求声明 `User-Agent` 并遵守 10 请求/秒 | XBRL `companyfacts` 对**同一期间保留多次 `filed` 记录**，重述天然可见 | 高：金额、期间、单位、申报类型全部结构化 | **采用** |
| 港交所披露易 | 条款未明确允许批量抓取与再利用 | 需人工比对 PDF | 低 | 不采用 |
| 巨潮资讯（A 股） | 站点条款限制抓取 | 需人工比对 | 低 | 不采用 |
| 商业数据商 | 需付费与合同 | 好 | 高 | 本阶段不采用 |

选择 EDGAR 的关键理由不是「免费」，而是**重述关系本身就是结构化数据**：同一 `(cik, tag, start, end)` 在 `companyfacts` 里会出现多条不同 `filed` 的 `val`，后一次与前一次的差就是重述。这让「时间是考官」从一句口号变成一个可执行的 diff。

### 1.2 语料定义

| 项 | 定义 |
| --- | --- |
| 主体队列 | 按 CIK 升序取前 **50** 家满足全部纳入条件的公司 |
| 纳入条件 | ① 有 FY2022/FY2023/FY2024 连续三个财年 10-K；② 使用 `us-gaap` 分类法；③ 非金融业（SIC 6000–6999 排除）；④ 合并口径下可取得 `Revenues` 或 `RevenueFromContractWithCustomerExcludingAssessedTax` 与 `GrossProfit` |
| 期间 | FY2022 → FY2023 → FY2024，构成 **2 个相邻年度对/公司** |
| 任务单元 | `(cik, pair)`，pair ∈ {FY22→FY23, FY23→FY24}，合计 **100 对** |
| 冻结 | 队列在取数前按上述规则机械生成，写入 `corpus-freeze.json`（只含 CIK、财年、tag、哈希），任何后续增删需新版本 |

队列选择规则必须是**机械且可复现**的：按 CIK 升序 + 固定纳入条件，不按行业、不按市值、不按「看起来有重述」。任何人工挑选都会破坏后面的失败率统计。

### 1.3 使用权与合规

- 只访问 `data.sec.gov` 与 `www.sec.gov/Archives`，请求头带可联系到的 `User-Agent`，速率 ≤ 10 请求/秒。
- 只取**已公开申报**，不取任何非公开、付费或受限材料。
- 公有领域解决的是**版权**，不解决事实正确性，也不自动构成训练授权。本协议不产出训练集。
- 原始正文与 XBRL 实例只落在 Git 忽略的 `work/pilot/`（0700 目录、0600 文件），Git 里只放哈希、计数与脱敏摘要。

### 1.4 明确排除

- 金融业（报表结构不可比，会污染失败类型分布）。
- 市值/行业特殊样本、SPAC、外国私人发行人（20-F）、双层股权结构的特殊披露。
- 任何需要人工挑选才能「凑够重述」的样本。

## 2. 任务与标签：让未来披露当考官

### 2.1 任务的形式化

对每个 `(cik, pair)`：

```
输入：公司 C 在 FY_t 与 FY_{t+1} 的合并口径 收入 与 毛利
输出：{
  comparable: boolean,          // 两期毛利率是否可比
  margin_t: number | null,      // 百分比
  margin_t1: number | null,
  changePp: number | null,      // 百分点变化
  basisFactIds: string[],       // 结论依据的事实
  blockers: string[],           // 不可比的具体原因
  stopReason: string | null     // 停止而非计算的理由
}
```

注意输出是**结论对象**，不是动作名。评分对象是结论是否被证据支持、是否被后续披露证伪，不是「选了哪个动作」。

### 2.2 三层标签

| 层级 | 标签来源 | 判据 | 强度 |
| --- | --- | --- | --- |
| **L-A 机械可判** | XBRL `companyfacts` 同一期间的多次 `filed` | `val` 变化超容差 → `RESTATED` | **强负**：直接证伪先前结论 |
| **L-B 语义可判** | 后续申报的注脚（recast / reclassified / revised / change in accounting policy / ASC 606 采用） | 需要读文本，机械只能定位候选段 | 中 |
| **L-C 不可观测** | 该期间已不在后续比较列中，或后续申报本身冲突 | 无标签 | **必须排除，不计为成功** |

### 2.3 重述检测算法（L-A）

对每个 `(cik, tag, start, end)`：

```
series = companyfacts[cik].facts["us-gaap"][tag].units["USD"]
              .filter(f => f.start === start && f.end === end)
              .sort(by filed, then accn)

v_first  = series[0].val            // 首次申报值
v_latest = series[-1].val           // 最近一次申报值（含 10-K/A 与后续年报比较列）

label = |v_latest - v_first| > tolerance(v_first) ? RESTATED : UNCHANGED
delta = v_latest - v_first
```

要点：

- **容差**：`tolerance = max(1, round(|v_first| × 1e-4))`，即万分之一。低于此视为同一数值的舍入差异，避免 `decimals` 属性差异造成假重述。
- **同一 `accn` 去重**：同一申报内的多条记录只取一条，防止重复计数。
- **单位与量纲**：只接受 `USD` 单位，`val` 按原值比较，不做千/百万换算。
- **两次以上变化**：记录全部变化点，标签取首次与最近之差，同时保留中间序列供失败分析。
- **`RESTATED` 的方向**：收入下修、上修、毛利重分类都算。方向不影响标签，但进入失败类型分类。

### 2.4 标签的强度是不对称的

这一点必须写在报告里，不能含糊：

| 观测 | 能证明 | 不能证明 |
| --- | --- | --- |
| `RESTATED` | 先前基于 v_first 的可比性结论**被证伪**（输入实质变化） | 不证明模型「错在哪个环节」 |
| `UNCHANGED` | 输入在后续申报中保持稳定 | **不证明结论正确**。数字没动不等于口径判断对 |
| `NOT_OBSERVABLE` | 无信息 | 不能计为成功，也不能计为失败 |

因此主指标不能用「准确率」，必须用**可证伪事件率**：在可观测样本里，被判为「可比并给出数值」的结论中，有多大比例后来被 `RESTATED` 打脸。这是唯一方向明确的量。

### 2.5 冲突与不可观测的处置

- 同一期间在 `companyfacts` 中出现 `RESTATED`，但后续注脚声明是「重分类且净利润不变」→ 标签降级为 `RECLASSIFIED`，单独统计，不与 `RESTATED` 合并。
- 该期间在后续两期 10-K 中都不再出现 → `NOT_OBSERVABLE`，从分母剔除，并在报告里给出剔除率。
- 后续申报本身互相冲突（例如 10-K/A 之后又被再次修正）→ 保留全部序列，标 `CONTESTED`，不参与主指标。

## 3. 规则基线：推到顶，然后量残差

### 3.1 规则阶梯

每一级只在前一级无法决策时启动，成本递增：

| 级 | 名称 | 判据 | 成本 |
| --- | --- | --- | --- |
| **R0** | 结构匹配 | XBRL context 的 period（start/end）、unit（`iso4217:USD`）、scope（无 segment 维度 = 合并）、basis（`us-gaap`）四项全部一致 | 纯 JSON，零成本 |
| **R1** | 申报内一致性 | 同一 accession 内，收入与毛利的 context 必须完全相同；不同则拒绝 | 纯 JSON |
| **R2** | 跨期连续性 | 同 CIK、同分类法、财年连续、无 `RestatementOf` / `RevisionOf` 关系标记 | 纯 JSON |
| **R3** | 披露事件检测 | 该期间存在 10-K/A、8-K Item 4.02（不再依赖先前财报）、或注脚出现 recast/reclassified/revised 关键词 | 正则 + 文本定位，零依赖 |
| **R4** | 口径桥接 | non-GAAP → GAAP 对账表、分部 → 合并桥接、会计政策变更的追溯调整 | 需要解析表格结构，开始大量失败 |

**R4 是刻意保留的失败点**。它的失败不是缺陷，是待测量的残差。协议不要求 R4 做对，只要求它**诚实地说自己做不到**。

### 3.2 「规则失败」的两类定义

| 类型 | 定义 | 可测性 |
| --- | --- | --- |
| **F-无决策** | 阶梯跑完仍无法输出 `comparable` 与数值，只能输出 `blockers` | 直接可数 |
| **F-被证伪** | 规则输出了「可比 + 数值」，但该期间的后续披露为 `RESTATED` | 需等标签，但机械可判 |

只有这两类算失败。规则输出「不可比 + 原因」且原因被后续披露证实（确实重述）的，是**成功**，不是失败。

### 3.3 失败类型分类（固定枚举）

```
MISSING_FACT            期间存在但缺收入或毛利
UNIT_MISMATCH           两期单位不同（含千/百万）
SCOPE_MISMATCH          合并 vs 分部，或并购导致范围变化
BASIS_MISMATCH          us-gaap vs ifrs-full，或政策变更未追溯
RESTATEMENT_AMBIGUOUS   存在重述但注脚未能判定方向或影响
NON_GAAP_BRIDGE         需要 non-GAAP → GAAP 对账
SEGMENT_BRIDGE          需要分部加总到合并
FISCAL_YEAR_CHANGE      财年变更（52/53 周、期间长度不等）
MULTI_CLASS             多类别股票导致每股/权益口径歧义
PERIOD_NOT_ALIGNED      两期起止日期不对齐
OTHER                   其余，必须附具体原因
```

分类表在取数前冻结。后续新增类别需要新版本，且旧结果不重新归类——否则会不知不觉把难例挪进「其他」。

### 3.4 失败的成本代理

不是所有失败都值得上模型。用两个可机械计算的代理量：

| 代理 | 定义 | 含义 |
| --- | --- | --- |
| `materiality` | `|delta| / |revenue_t|`，或不可比时用缺失项的估计影响 | 这个数字变动对结论的分量 |
| `consequential` | `materiality ≥ 1%` **或** 该期间后续 `RESTATED` | 失败是否真有后果 |

**残差 = F-无决策 ∪ F-被证伪 中 `consequential = true` 的子集。** 模型只在这个集合上被调用。

这条定义是整个协议的核心：它把「需不需要模型」从一个立场问题变成一个可以算出来的数。

### 3.5 主指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| `rule_coverage` | 规则能给出决策的对数 / 总对数 | 规则覆盖到哪 |
| `residual_rate` | F-无决策 / 总对数 | 残差规模 |
| `consequential_residual_rate` | 残差中 `consequential` 的比例 | **是否值得上模型** |
| `falsified_rate` | F-被证伪 / 可观测对数 | 规则自信但错的比例 |
| `not_observable_rate` | L-C / 总对数 | 标签可得性 |

### 3.6 样本量与诚实的不确定性

100 对在 p = 0.5 时的 95% 置信区间约 **±9.8 个百分点**。这意味着：

- 本阶段只能判断「残差是大是小（比如 >20% 还是 <5%）」，**不能**判断「模型提升了 3 个百分点」。
- 报告必须给出置信区间，不得只报点估计。
- 只有当 `consequential_residual_rate` 明显不为零（例如点估计 > 10% 且下界 > 5%）时，才扩大到 200 家 / 400 对。扩大后精度约 ±4.9pp。

## 4. 1 美元闭环：门控与预算上界

### 4.1 预算分解

硬上限：**1,000,000 µUSD**，写入 `grant.maxCostMicrousd`。这不是预期花费，是**不允许突破的天花板**。

| 项 | 设定 | 依据 |
| --- | --- | --- |
| `maxCostMicrousd` | 1,000,000 | 本协议授权上限 |
| `maxCalls` | 由 4.2 公式反推，上限 200 | 防止单条重试吃掉预算 |
| `maxInputBytes` | 20,000 | 沿用既有 route 默认 |
| `maxOutputTokens` | 512 | 输出是结构化结论，不是长文 |
| `maxConcurrent` | 1 | 串行，便于归因 |
| 单价 | 由主机在授权时复核并冻结为 `pricingHash` | **不得使用任何历史或记忆中的价格** |

单次调用最坏预留：

```
inputTokenBound = inputBytes + 512
costReservation = ceil((inputTokenBound × P_in + maxOutputTokens × P_out) / 1e6)
maxCalls        = floor(1,000,000 / costReservation)
```

`P_in` / `P_out` 是授权时填入的每百万 token 微美元单价。**本文件不写具体价格**，因为价格会变，写死就是伪造。

示例（仅为说明算术，**不是报价**）：若单次预留为 6,000 µUSD，则 `maxCalls = 166`，足以覆盖 100 对样本的全部残差（残差率即使 100% 也只需 100 次）。

### 4.2 门控链（全部复用既有机制，不新增旁路）

每次调用必须依次通过，任一失败即不发送：

1. `authorizer` 返回**当前** grant，且与任务创建时逐字段相同（`MODEL_CURRENT_AUTHORIZATION_DENIED`）。
2. 预算预检：`budgets.preflight` 检查配额、token 上界、费用上界、并发 lease。
3. 传输批准：精确匹配 request / principal / grant / route config / pricing / prompt hash，有效期 ≤ 1 小时。
4. `credentialProvider` 在 dispatch 时才解析凭证；凭证只进单个 `Authorization` 头，不落盘、不进日志。
5. 原子预留 → 落 intent → dispatched → 发送。
6. 返回后写签名收据（含 usage 与费用估算），`actualCostMicrousd: null`，`externalBilling: 'not-verified'`。

**必须显式接受未证实的计费上界**（`acceptUnprovenTokenAndBillingBounds: true`）。这是承认风险，不是证明上界。

### 4.3 模型输出契约

模型只允许输出一个 JSON 对象，字段与 2.1 完全一致，额外字段一律拒绝。约束：

- `basisFactIds` 必须是本次输入中**真实出现**的事实 id，且至少一个。
- `margin` / `changePp` 由 Runtime 用确定性算术重算，与模型给出的值不符即判 `RESULT_VERIFICATION_FAILED`。
- 模型不得输出风险等级、信用结论、权限、凭证、完成声明。
- 解析失败 → `confirmed-invalid` 收据，**不执行、不计入成功**。

### 4.4 unknown 与真实失败

这是本协议要拿到的**最有价值的信息**，不能被美化：

| 情况 | 处理 | 记录 |
| --- | --- | --- |
| 发送后超时 / 中断 / 5xx | `unknown`，预留不退，lease 不释放，**不自动重发** | 计入真实成本，计入失败 |
| 有可信匹配收据 | 只能显式 `reconcile` 确认 | 计入真实成本 |
| 无收据 | 继续阻断，人工决定是否放弃该条 | 计入真实成本，标 `UNRESOLVED` |
| 输出非法 | `confirmed-invalid`，不执行 | 计入成本，计入失败 |

**真实失败必须计入单位成本**。把 unknown 排除在分母外，等于自己给自己刷分。

### 4.5 停止规则（任一触发即停）

| 条件 | 动作 |
| --- | --- |
| `consequential_residual_rate` < 5% | 停止。规则已足够，上模型无意义，出报告 |
| 单条 unknown 超过 2 小时未对账 | 停止。先解决对账，不进入下一批 |
| 累计预留 > 800,000 µUSD | 停止。留 20% 余量，不赌 |
| 任一调用绕过了门控链 | 立即停止并保留现场 |
| 真实单价与授权时冻结的快照不一致 | 停止，重新授权 |

## 5. 判分与经济账

### 5.1 指标

```
coverage_gain     = (规则正确 + 模型新增正确) / 总对数 − 规则正确 / 总对数
cost_per_resolved = 模型总花费 / 模型新增且被独立验证为正确的条数
falsified_after   = 模型给出的结论中后来被 RESTATED 证伪的比例
```

`cost_per_resolved` 必须包含 unknown 的花费，这是它唯一诚实的分母定义。

### 5.2 决策规则

| 观察 | 决策 |
| --- | --- |
| 残差 < 5%，或 consequential 残差 < 5% | **NO_GO**：规则已足够，停止，不蒸馏 |
| 残差显著但 `cost_per_resolved` 高于专家复核成本的 1/10 | **NO_GO**：不划算 |
| 残差显著、成本可接受，但两个独立 cohort 的残差率差异 > 5pp | **HOLD**：残差不稳定，先查数据而非上模型 |
| 残差显著、成本可接受、跨 cohort 稳定 | **GO 到规模评估**：才进入「年调用量 × 单条成本 vs 蒸馏一次性成本」的计算 |
| 任何阶段出现 unknown 未对账 | **HOLD**：先闭合对账 |

**只有最后一档才谈蒸馏**，且必须先算出「API 年成本 > 蒸馏成本 × 3」这个不等式成立。

## 7. 不证明什么（NOT_PROVEN）

- 不证明模型优于规则。100 对样本、单一语料、单一供应商，不足以支撑任何优越性结论。
- 不证明 EDGAR 数据的「事实正确」。公有领域只解决版权，审计过的数字仍可能错。
- `UNCHANGED` 是弱证据，不证明口径判断正确。
- 不证明真实计费准确。`actualCostMicrousd` 恒为 `null`，`externalBilling` 恒为 `not-verified`。
- 不证明断电、磁盘损坏、多机一致性。
- 不产生任何可训练数据、任何投资或信贷建议。
- 不证明跨市场可迁移（只覆盖美国 `us-gaap` 申报主体）。

## 8. 需要批准的清单

执行前需逐项书面确认：

1. **数据源与使用权**：仅 `data.sec.gov` + `www.sec.gov/Archives`，声明 `User-Agent`，速率 ≤ 10 req/s，只取已公开申报。
2. **语料冻结**：CIK 队列生成规则、期间、纳入/排除条件，及其哈希。批准后不得按结果调整。
3. **数据落盘**：原始正文与 XBRL 只进 `work/pilot/`（0700/0600），Git 只放哈希与计数，保留期与删除责任。
4. **标签算法**：2.3 的重述检测、容差、`NOT_OBSERVABLE` / `RECLASSIFIED` / `CONTESTED` 处置，冻结后不改。
5. **规则阶梯与失败定义**：R0–R4 与 F-无决策 / F-被证伪的定义，以及失败类型枚举。
6. **模型预算**：$1 硬上限、授权时复核并冻结的单价快照、由此推出的 `maxCalls`、token 上界、`maxConcurrent = 1`。
7. **传输授权**：逐调用一次性批准（≤1h）、`credentialProvider`、显式接受未证实计费上界。
8. **停止与留痕**：4.5 的停止规则、失败证据保留位置、unknown 对账责任人。
9. **不做清单**：不训练、不蒸馏、不抓未授权源、不读真实密钥以外的凭证、不 push 未经审查的产物。

未获上述批准前，本协议不产生任何真实网络请求、不读取任何凭证、不花费任何金额。
