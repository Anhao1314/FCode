# Paper & Proof / 纸与证

产品理念全文：`flowcredit/docs/philosophy.md`。

FCode 的界面不是聊天窗口，而是一张**可复核的工作底稿**。这套设计语言从早期的
纸墨风格收敛而来，目标不是“像某个品牌”，而是让用户一眼感到：这是一份可以签字的东西。

在线样式页：`flowcredit/viewer/design.html`（本地启动 console 后访问 `/design.html`）。

Agent 面向的架构与交互约束：`.agents/skills/fcode-design/SKILL.md`。改 UI 前先读它。

## 六条原则

1. **纸是底稿。** 白底、留白、细线、虚线分隔；界面像一张可以归档的纸，不是仪表盘。
2. **墨只表达确定。** 近黑墨色承担结论；颜色只用于已验证、待确认、错误三种状态。
3. **手写是人的痕迹。** 楷体只出现在标题、结论、人工决定；机器数据用无衬线或等宽。
4. **数字像账本。** 金额、比例、哈希用等宽与 tabular numerals，对齐优先于装饰。
5. **线是校对痕。** 实线分区，虚线表示可裁切/可归档；不用阴影伪造层级。
6. **动效是翻页。** 160–220ms 淡入/位移；手绘小人只在运行时呼吸，不做弹跳。

## 类型层级

- **Display 27–38px 楷体**：页面标题、报告抬头。不超过两行。
- **Section 18–21px 楷体**：章节标题、结论短句。
- **Body 12.5–14px 无衬线**：说明、正文。
- **Meta 9–10px 等宽，字距 .12em**：CASE FILE、PREFERENCES、链头、时间。
- **Number 等宽 + tabular-nums**：比例、金额、哈希、预算。

## 标志性组件

### 案卷抬头

```
CASE FILE   console-operator
判断恒星智算 2024 与 2025 两期合并毛利率是否可比
Fcode · 9 轮 · 49 个事件 · 全链验证通过
```

等宽 kicker + 楷体目标 + 等宽元信息。所有页面共用这个语法：
`WORKBENCH` / `CASE FILE` / `NEW DELEGATION` / `PREFERENCES`。

### 校对线

成功结论数字下方固定出现：

```
[✓ 已复算]  Runtime 独立重算通过 · 2 处引用 · 49 个事件
```

它不是装饰，是“这个数字敢签字”的视觉承诺。没有经过复算的结论不能出现这个标记。

### 选择卡

- 2–4 个具体结果，不是抽象分类。
- 每个选项是“标题 + 一句为什么”，推荐项有 badge。
- 选中态用墨色边框和浅纸底，不用彩色填充。
- 选择卡不是问卷：先有模型回复，再有选项。

### 判断面 / 判断记录

- **判断面**不是答案卡：事实、异常、2–3 种解释、待判断、什么会改变结论依次排列。
- 没有证据的解释不能写成结论；失败的运行不补解释，只列出 failure code/message。
- **判断记录**是四种人决定：接受判断 / 需要补材料 / 保留意见 / 退回重做。
- 需要理由的决定必须写理由；提交后追加 `review_decided` 事件，不改运行终态。
- 静态回放没有可写入的 run id，只显示只读说明，不给假按钮。
- 视觉：判断面用 12px 纸卡、虚线分隔、等宽小标签；决定按钮用墨色选中态，不用彩色填充。

### Reviewer profile

- 历史判断只做参考：显示同类次数、四种决定计数、上次决定与理由。
- “采用上次判断”只选中决定并填入上次理由，**绝不自动提交**。
- 没有历史、加载失败或静态回放时不显示假数据；静态回放不显示写入按钮。
- 判断记录可追加，不覆盖；报告只取最近一次，并附 reviewer、事件序号与 hash。
- 视觉：虚线分隔、等宽计数、纸色底，不做彩色置信度条或“AI 建议”徽章。

### 状态

- 已验证：绿色小点 + 短标签；不铺满。
- 待确认：琥珀色；只出现在真正需要人的地方。
- 错误/阻塞：砖红；必须同时给出稳定错误码。
- 颜色永远与文字标签一起出现，不能只靠颜色区分。

## 动效

- 页面/面板进入：淡入 + 8px 位移，220ms。
- 开关/悬停：160ms。
- 手绘小人：只在 live 状态呼吸；静态页面不循环播放。
- 支持 `prefers-reduced-motion` 和设置里的动效总开关。
- 不用弹簧、缩放弹跳、视差。

## 文案语气

- 说“核查、复算、出处、底稿、阻塞”，不说“智能涌现、魔法、一键封神”。
- 结论先行，证据随后；每个数字有单位、期间、来源。
- 失败要具体：缺哪份材料、哪一步阻塞、下一步能做什么。
- 不用感叹号；不用 emoji 代替状态。

## 做与不做

**做**

- 用留白、细线、虚线组织信息。
- 让每个数字旁边有来源或“未验证”标记。
- 手写体只用在标题、结论、人的话。
- 状态色只表达状态。

**不做**

- 渐变、发光、玻璃拟态、AI 紫。
- 大面积阴影或多层浮起卡片。
- 所有东西都做成胶囊按钮。
- 用 emoji 或 3D 图标代替手绘线稿。
- 为了“高级感”牺牲可读性或审计线索。

## 实现约定

1. 新样式只写 `viewer/design.css`；旧 `app.css` 只做布局兼容。
2. 不新增颜色；确需新状态时先加 token，并在本文档登记。
3. 任何“已验证/已复算”标记必须有 Runtime 重算或链验证作为依据。
4. 组件改动后至少检查：运行页、设置页、需求确认页、报告页、窄屏。
5. 视觉验收以 `design.html` 和真实页面双重为准。
