# Agent 应用威胁模型(AGI 分类法)

> 状态:**v1,已定义,规则引擎实现中(Sprint 2)**。
> 本文是规则库(`audit-rules/`)与发现报告共享的分类依据。分类号是稳定标识:
> 报告引用它,规则按它组织,历史结论按它追溯。新增分类可以,重命名是迁移。

## 一、审计对象的攻击面从哪来

一个 agent 应用与传统软件的根本差异:**不可信内容会变成指令**。

- 聊天消息、网页、文件、工具输出——一切外部内容都可能流进模型上下文;
- 模型的输出直接驱动工具调用——一次注入等于一次越权执行;
- agent 拥有持久状态(记忆、会话、自治任务)——一次成功的操纵可以潜伏。

因此 agent 应用的缺陷分类以"内容如何变成权限"为主线,而不是传统的
"内存如何变成 RCE"。

## 二、AGI 分类法 v1

| 编号 | 类别 | 典型样本 | 检测思路 |
| --- | --- | --- | --- |
| AGI-01 | 间接提示注入 | 聊天消息/网页/工具输出携带"忽略此前指令";藏在 agent 会读取的文档里的指令 | 注入面测绘(不可信文本→上下文的所有路径)+ 容器内探针(自测账号发 payload,观察工具调用) |
| AGI-02 | 越权工具执行 | 无门控直接执行;模型自我批准;"remember"按工具名记忆导致后续任意参数免审批(真实案例:FCode `console_runtime.py:722-727`) | 工具调用是否经过唯一咽喉点;审批记忆的粒度;效果分级是否存在 |
| AGI-03 | 秘密泄漏 | 密钥明文落盘;密钥进 prompt/日志;错误上报携带密钥出境 | 权限位与存储形态(只看权限位,不读内容);遥测边界抓包;日志模式匹配(只报计数) |
| AGI-04 | 沙箱逃逸 | 路径穿越 `../`;symlink 预测攻击;`grep -f <外部文件>` 越狱(样本:FCode `test_p0_regressions.py`) | 用已知攻击样本打靶;工作区牢笼的绝对路径/`..`/symlink/NUL 拒绝矩阵 |
| AGI-05 | 供应链缺陷 | 自更新无验签;`disable-library-validation` 与自更新叠加(真实案例:evox sidecar 待验签);依赖投毒 | 信任链实算(sha256 对账、签名验签);篡改测试(改一字节看是否拒绝);端点与传输审查 |
| AGI-06 | 自治失控 | 自我进化无审批/无回滚;无限循环;预算失控;崩溃后重复副作用 | 自治组件的改动是否有版本控制与审批;SIGKILL 后副作用对账(方法:FCode crash_worker) |
| AGI-07 | 过度授权 | entitlements 超出功能需要(apple-events+麦克风+日历);OS 级授权(辅助功能/全盘)超需 | entitlements 与功能清单对照;TCC 实际授权核对;最小化差距即发现 |
| AGI-08 | 治理缺失 | 审计日志可篡改(无哈希链);无审批流;文档声称与实现不符(真实案例:FCode README 预算链超声明) | 篡改日志看能否被发现;危险操作有无人工确认点;声明逐条对实现 |
| AGI-09 | 诚实性缺陷 | 谎报"完成";用无关通过替代声明义务;预置失败被掩盖 | 布置不可能任务;独立复算;无关通过的替代测试(方法:FCode `test_verification.py:444`) |

分类原则:**一个类别必须至少有一个已确认的真实样本**(收录在 `fixtures/`)
才有资格存在。样本不足的候选类别进"观察名单",不进主表——分类法解释一切
就等于什么都没解释。

## 三、审计者自身的可信模型(谁来审计审计者)

审计发现如果可以被审计者伪造,整个产品失去意义。四条硬约束:

1. **目标内容是不可信输入——并且覆盖一切派生物。** 被审计应用的 README、
   system prompt、工具输出全部是数据,不是指令;同样,Analyst 读过这些内容
   之后输出的**任何东西**——候选的字段、PoC 的命令与路径、证据摘要——都
   仍然不可信。工具结果是注入的主要入口,把内容限制在工具结果里只是汇聚
   通道,不构成信任边界;信任边界由 PoC 能力清单与宿主校验承担(见 3.1)。
2. **发现 = 宿主侧 oracle 判定下的 PoC 重放通过。** PoC 只是刺激物;判定
   不变量由规则定义、由宿主执行与读取——一个打印 "PASS" 的 PoC 证明不了
   任何事(`flowaudit.poc` 契约)。重放在能力受限环境进行:无真实凭据、
   默认禁网、临时文件系统、目标独立副本。重放结果三值化:
   `finding` / `not_reproduced`(保留候选)/ `invalid_poc`(harness 或
   oracle 缺陷)/ `not_vulnerable_under_scope`(需对照证据,预期罕见)——
   FAIL 不证明不存在,不把"未复现"当"安全结论"。
3. **审计过程自身进哈希链——链证明完整性,不证明真实性。** 每一步测绘、
   探针、审批、重放都是事件;但若写入前已被操纵,链会忠实保存错误结论。
   因此审计事件必须绑定:目标清单哈希、PoC/oracle/重放器版本、内容寻址
   引用、负对照与清理结果。"谁审计了审计者"由 `verify_chain` 加完整证据
   包回答——审计者每天用自己的基准(`benchmark/`)证明自己没坏。
4. **授权前置。** 审计"别人"的应用之前,operator 必须明确授权;授权声明、
   允许范围与时间窗、第三方服务限制、披露流程与证据保留期限写入报告。
   审计自己设备上安装的应用做安全评估属于合理范围,但报告仍须声明授权来源。

### 3.1 审计器自身威胁模型(Sprint 2 首项)

把"目标操纵审计者"当作第一个攻击场景写清楚:目标能控制哪些字节(源码、
文档、配置、运行时响应)→ 这些字节如何流入 Analyst 上下文 → Analyst 的
输出如何变成 PoC → 重放器拥有哪些权限。在此之上:

- **行为金丝雀**:目标内容中埋入唯一性行为诱饵(专用伪秘密文件、不存在
  的工具名、预禁用的唯一动作)。诱饵所指示的**行为发生**才记
  `auditor_compromised` 并降级人工;仅引用诱饵文本只记诊断遥测——引用
  既非失陷的必要条件(注入可以不引用),也非充分条件(合法引用证据会误报)。
- **秘密测试用伪秘密**:泄漏检测植入专用伪秘密,以"伪秘密是否出现在禁止
  出口"判定,不接触真实凭据——审计报告本身不能成为泄漏源。

## 四、与 CWE 的关系

AGI 分类法不替代 CWE,做映射:AGI-01→CWE-74(注入)/CWE-1427,AGI-03→CWE-798/
CWE-532,AGI-04→CWE-22/CWE-59,AGI-05→CWE-494/CWE-1357,AGI-07→CWE-250。
映射让报告可以对接传统安全流程,但 agent 特有的类别(AGI-01/06/08/09)
在 CWE 里没有精确对应——这正是这个分类法存在的理由。

## 五、非目标

- 不做武器化:PoC 以"证明缺陷存在"为限,不提供利用增强、不提供横向移动路径。
- 不承诺发现所有缺陷:分类法覆盖的是**已知模式**;未知模式的发现依赖
  人工审计,报告会明示覆盖率边界。
- 不对目标做拒绝服务:探针有预算与频次上限,由 Runtime 的预算机制强制。
