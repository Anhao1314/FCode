# FCode 理念：能被签字的智能

> 我们不生产更会说话的 AI，我们生产能被签字的结论。

## 一、我们为什么存在

数字经济的瓶颈已经不是“生成内容”，而是“承担责任”。

模型可以写出一段像模像样的分析，但分析师不敢把它交给合伙人，信贷员不敢把它交给信审会，顾问不敢把它交给客户。因为没有人能回答三个问题：

- 这个数字从哪来？
- 中间改过什么？
- 出错的时候，系统会不会更糟？

FCode 的存在，就是把这三个问题变成产品本身：**模型只提议，主机做决定，证据进链，结论可复算。** 智能可以外包，责任不能外包。

## 二、八条信念

### 1. 模型不掌权

模型可以提议动作，但不能授权自己、不能执行、不能改预算、不能宣告完成。
工具是封闭注册表，参数按 schema 校验，调用必须同时出现在任务范围和主机 grant 里。
**用户感受：它不会背着我动钱、动数据、动结论。**

### 2. 可信不是模型属性，是系统属性

再强的模型也会错。可信来自系统：证据、独立复算、签名收据、哈希链、崩溃恢复、未知结果不重发。
**用户感受：每个数字能点回原文，每一步能重放。**

### 3. 先有证据，再有结论

每个数字必须带单位、期间、来源；没有来源的数字明确标“未验证”。
缺资料时停下，不编一个看起来合理的数。
**用户感受：这份东西我能签。**

### 4. 不确定时，停下来比猜下去更有价值

超时是 unknown，不是“再试一次”；缺桥接材料是阻塞，不是“用相近口径代替”。
失败必须具体：缺哪份材料、卡在哪一步、下一步能做什么。
**用户感受：它出错的时候，不会把问题变得更大。**

### 5. 记忆不是第二套事实，是证据的投影

案例簿和事实簿从签名轨迹确定性投影而来；修正追加，不覆盖；删除只写墓碑。
记忆不靠模型“回忆”，靠可回放的来源。
**用户感受：它记得，但不编。**

### 6. 选择不是问卷，是理解的脚手架

用户先说话，agent 先回复；选项从理解中长出来，而不是一进门就抛三页表单。
最多三个高价值问题；能推断的不问；随时能改、能退、能直接描述。
**用户感受：它在听，不是在收集字段。**

### 7. 界面是一张底稿，不是模型的舞台

纸是底稿，墨是结论，线是校对痕。手写只留给人的判断，等宽只留给机器的证据。
没有渐变、发光、玻璃拟态、AI 紫；没有假控件；没有用颜色代替文字的状态。
**用户感受：这是一个工作的地方，不是一个演示。**

### 8. 审美不是装饰，是信任的界面

零阴影、细墨线、虚线分隔、校对章、可签发的底稿，都是“这句话可以负责”的视觉表达。
如果界面让人感觉浮夸、模糊、不可核对，信任已经在第一眼流失。
**用户感受：我愿意把客户资料和名字放在这里。**

## 三、我们为谁做

**林岚，32 岁，精品尽调 / 风险咨询团队的项目负责人。**

- 她的核心资产不是时间，是**判断力、标准和签名**。
- 她最擅长的五个判断：
  1. 看出两期数字其实不可比（单位、准则、合并范围、重述）；
  2. 判断异常是业务变化还是会计处理；
  3. 决定证据够不够签字；
  4. 把复杂发现讲成合伙人/客户能接受的结论；
  5. 把自己的标准传给 junior。
- 痛点只是约束：PDF/Excel 搬运、单位/口径核对、引用错误、资料不能上云。它们解释为什么现在慢，但不定义产品价值。
- 她不怕 agent 慢，怕 agent 给一个她不敢签字的数字。

她的一句话：

> “我不需要它替我签字，我需要它把每个数字的出处摆到我能签字。”

### 优势观：不替代判断，放大判断

痛点导向会做成更快的搬报表工具；优势导向才会做成判断放大器。

| 她的优势 | 框架怎么放大 |
| --- | --- |
| 判断数字不可比 | 把单位/口径/重述差异摆成判断面，不直接给结论 |
| 判断异常性质 | 给 2–3 种解释、反证、还需要什么证据 |
| 判断证据是否足够 | 明确 blocked / limitation，不替她拍板 |
| 讲给合伙人/客户 | 给多种表述草案、保留措辞和适用条件 |
| 把标准传给 junior | 记录 accept / reject 理由，形成 reviewer profile |

Agent 的职责不是“替她做判断”，而是让她**做更多只有她能做的判断**，并让这些判断可复用。

**反人设**：想听股票建议的散户、只要 API 的开发者、上来就要私有化平台的大型企业。不是他们不重要，而是现在不该为他们改产品。

## 四、理念怎么落到工程

| 信念 | 工程落点 | 用户感受 |
| --- | --- | --- |
| 模型不掌权 | `permissions` / `budget` / `harness` / 封闭工具注册表 | 不会背着我动钱、动数据 |
| 结论可复算 | Evidence Authority / 独立 verify / trace 重算 | 每个数字能点回去 |
| 不确定不重发 | 签名收据 / `recovery_required` / 显式对账 | 出错不会更糟 |
| 记忆可回放 | 案例簿 / 双时态事实簿 / `binding.spec` | 它记得，但不编 |
| 选择先于执行 | `intake` / `TaskSpec` / 任务卡 / 预算可见 | 它先问我，不替我猜 |
| 纸与证 | `design.css` / 校对线 / 案卷抬头 / 状态色 | 这份东西我能签 |
| 放大判断 | 判断面 / 解释候选 / reviewer profile | 我只做只有我能做的判断 |
| 失败要具体 | 稳定错误码 / blocked reason / 下一步 | 我知道该补什么 |
| 本地优先 | 桌面端 / 本机偏好 / 主机持有凭证 | 客户资料不出本机 |

## 五、交互观

- **先听后问。** 用户的消息是主输入；选项是理解的产物，不是开场问卷。
- **选项是结果，不是分类。** “判断两期能不能直接比”比“选择分析类型”更像人话。
- **花钱前看见预算。** 任务卡必须显示轮次、成本、审批；不能先跑再解释。
- **用户永远有出口。** 能改、能退、能取消、能直接描述；不把用户困在流程里。
- **运行中不假装。** 审批停在轮次边界；拒绝有原因；unknown 不伪装成成功。
- **失败也是产品。** 阻塞页要告诉用户缺什么，而不是只给一个红色错误。

## 六、审美观

**Paper & Proof / 纸与证。**

- 纸是底稿：白底、留白、细线、虚线分隔。
- 墨是结论：近黑承担确定；颜色只表达已验证、待确认、错误。
- 手写是人的痕迹：楷体只用于标题、结论、人工决定。
- 数字像账本：等宽 + tabular numerals；单位、期间、来源不能丢。
- 线是校对痕：实线分区，虚线表示可裁切/可归档；不用阴影伪造层级。
- 动效是翻页：160–220ms；手绘小人只在运行时呼吸。

签名组件：

- **案卷抬头**：`CASE FILE` / `WORKBENCH` / `NEW DELEGATION` / `PREFERENCES`。
- **校对线**：`✓ 已复算 · Runtime 独立重算通过 · 2 处引用 · 49 个事件`。
- **选择卡**：2–4 个具体结果，标题 + 一句为什么，推荐项有 badge。
- **印章**：链验证、报告签发；状态色只在章内出现。

## 七、架构观

- **事件链是唯一事实源。** UI 只是链的阅读器；任何只在内存里的“真相”都不可信。
- **验证与执行分离。** 模型不能宣告完成，只有 Runtime 复算通过才算成功。
- **工具是权限，不是能力清单。** 模型看得见不等于能调用；任务范围 + grant 同时成立才行。
- **记忆是投影，不是缓存。** 案例/事实可从轨迹重建；修正追加；删除只墓碑。
- **本地是默认，不是补丁。** 客户资料、凭证、运行记录优先留在本机。
- **选择要落盘。** 用户选了什么，必须进入 `binding.spec`；否则不可回放、不可审计。

## 八、我们不做什么

- 不做“什么都能聊”的通用聊天机器人。
- 不做自动交易、投资建议、替用户签字。
- 不追求“看起来智能”，追求“可以被复核”。
- 不隐藏预算、拒绝原因、阻塞原因。
- 不做没有后端支撑的假开关、假选项、假进度。
- 不用渐变、发光、玻璃拟态、AI 紫来伪装高级。
- 不把审美做成装饰；审美是信任的一部分。

## 九、什么算完成

一个任务算完成，不是模型说“完成了”，而是：

- 每个数字有来源、单位、期间；
- 独立复算通过；
- 链可重放，失败可解释；
- 用户能导出底稿，敢签字；
- 下一次同类任务能复用，而不是从零开始。

**如果不能被复核，就不算完成。**
