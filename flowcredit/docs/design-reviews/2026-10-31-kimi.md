# 设计评审记录:2026-10-31(Kimi 外部评审)

> 这是本项目的第一份**过程证据**:一份外部对抗性评审,逐条对照证据裁决后
> 合入设计。裁决原则与产品原则一致——外部模型的意见只是输入,采纳与否
 > 由证据和已冻结约束决定;采纳的进蓝图,反驳的说出理由。

## 一、评审方式

方案(定位、AGI 分类法、双模型机制、发现生命周期、反注入设计、Sprint 1 状态、
7 个自体缺陷 ground truth)以自包含 prompt 交付独立模型评审,要求对抗性输出
(总评/致命风险/机制级挑战/盲区/待决问题表态/诚实性检查/换位计划)。

## 二、评审核心结论(原文要点)

- **总评:有条件成立。** 作为"面向已授权、环境固定、宿主侧 oracle 可判定的缺陷,
  生成可复验证据的审计器"成立;作为覆盖九类的通用审计产品,当前不成立。
- **最脆弱一环**:目标可以影响 Analyst 生成 PoC,宿主随后执行该 PoC——审计器
  可能成为目标应用的 confused deputy。
- **五项致命风险**:① PoC 通道的权限外泄;② 重放 FAIL 系统性漏报("PASS 证明
  存在,FAIL 不证明不存在");③ 自审计循环验证(规则按 7 缺陷开发又用同 7 缺陷
  验收);④ 目标版本/配置未固定导致证据不可复现;⑤ JSON 规则表达力不足以覆盖
  九类。
- **六项机制挑战**:工具结果不是信任边界(派生物才是);verdict 不能由退出码或
  PoC 自报决定(oracle 必须宿主侧);类型化输出+校准置信度≠正确分诊(Jev 应
  shadow mode);金丝雀"引用即失陷"既不充分也不必要(应行为化);哈希链证明
  完整性不证明真实性(事件须绑定目标哈希与工具版本);锚定真实样本防凭空但不
  防过拟合(需保留集/变异/负对照)。
- **六项盲区**:第三方数据出域;秘密测试与"不读秘密"的冲突(应植入伪秘密);
  授权/披露/证据保留策略;覆盖率不能由已知缺陷分母表达;evox 关联偏差;发现
  需按根因归并。
- **待决问题表态**:Jev-as-tool(但移出关键路径,shadow mode);不保留 operator
  免检权;金丝雀 Sprint 2 做(行为式);静态/动态分会话(共享 audit_id 与不可变
  目标清单);评分卡现在定维度锚点、数据后置权重。
- **诚实性检查**:第二节存在把设计目标写得像已验证能力的倾向;"独立子进程"
  只能声称进程级独立;"无幻觉"是厂商主张;"自审计独立检出"应改称"已知样本
  回归检出"另设盲测。
- **两周计划**:收窄为可信证据闭环(PoC 合约先于规则数量;重放器当安全边界;
  保留集盲测;三个对抗性回归;Jev 只记录不裁决)。
- **最终验收建议**:"在保留缺陷和负对照上,第三方仅依据审计包即可重放结论,
  并且目标无法借 PoC 获得审计器权限。"

评审原文全文由会话归档;以上要点经与原文逐段核对,无失真。

## 三、裁决

49 条意见:**全盘采纳 27 / 修正采纳 17 / 保留意见 5 / 无一全盘否决。**

### 采纳为硬约束(改变蓝图)

1. **PoC 能力清单 + 宿主校验**(风险 1/3.1):PoC 声明能力范围,宿主校验实际
   执行不越界;重放默认禁网、无真实凭据、临时文件系统、目标独立副本。进程
   隔离 ≠ 能力隔离。
2. **状态机 v2**(风险 2):重放结果三分——`not_reproduced`(保留候选)/
   `invalid_poc`(harness 或 oracle 缺陷)/ `not_vulnerable_under_scope`(需
   对照证据)。PASS 仍是唯一晋升门,冻结约束不破。
3. **oracle 宿主侧**(3.2):PoC 只是刺激物;判定不变量由规则定义、宿主执行、
   宿主读取——复用 Runtime 既有"宿主义务重执行"模式。概率性缺陷预登记样本
   数与通过阈值。
4. **盲测纪律**(风险 3/3.6):dev 集 = FCODE-01/02/06;盲测集 = FCODE-04/07
   (不进规则、提示词与示例);FCODE-03/05 预留;另建无缺陷负对照与结构变异
   样本。"独立检出 ≥3"更名"已知样本回归检出"。
5. **证据包绑定**(3.5):审计事件绑定目标清单哈希、PoC/oracle/重放器版本、
   内容寻址引用、负对照与清理结果。
6. **会话拆分**(Q4,推翻原单会话设计):静态/动态分会话,共享 `audit_id` 与
   不可变目标清单;阶段间只传带哈希的结构化工件,不继承对话上下文。

### 采纳(设计修订)

- Jev:确认 Jev-as-tool,但 Sprint 2 仅 **shadow mode**(只记录不裁决);确定性
  哈希去重 + 规则过滤为基线;分诊数据出域需单独审批;"无幻觉"仅作厂商主张引用。
- 金丝雀 v2:行为式(伪秘密文件、不存在的工具名、唯一禁用动作),发生行为才记
  `auditor_compromised`;引用检测降级为诊断遥测。
- 规则/探针分离:局部可匹配模式用 JSON 规则(`trigger.type=static`);跨文件
  数据流与行为类缺陷用**版本化探针代码**(`trigger.type=probe`,规则按 id 引用),
  探针代码自带测试与评审纪律。
- 秘密测试改用**植入伪秘密**:以"伪秘密是否出现在禁止出口"判定,不接触真实凭据。
- evox 降级为**工程联调靶**;泛化能力证明改用无关联的开源 agent 应用。
- 发现按**根因归并**计分,不按 PoC 数量计分。
- 评分卡:现在定五维与逐档锚点,权重等数据,不合成总分,Jev 置信度不得直接
  当严重度权重。
- operator 处置词:`accepted_risk` / `false_positive_disputed` / `wont_fix`——
  均不产生 finding。
- 报告单列**未覆盖面与无法测试项**;授权/披露/证据保留策略进报告模板。
- 诚实性措辞:文档区分"设计目标/已验证能力";"进程级独立"替代"独立子进程"
  的安全暗示;差异化主张待竞品能力矩阵对照(TODO)。

### 保留意见(5 条,附理由)

1. "无 OS 级隔离不执行动态 PoC"应限定于 **PoC 重放**对象;驱动目标应用本身
   无法沙箱(它是审计对象),靠授权/备份/审批门控/honeypot 约束。两类分开
   写入方法论。
2. `not_vulnerable_under_scope` 的证据门槛应高到几乎不常用;大多数 FAIL 落在
   `not_reproduced` 并保留候选——这是诚实设计而非缺陷。
3. shadow mode 是 Jev 的**最快转正路径**而非缓刑:shadow 数据是未来论证其
   active 的唯一合法依据。
4. 规则/探针分离后,探针代码需要自己的测试与评审纪律(评审未展开,此处补上)。
5. 竞品对照(promptfoo/garak/deepeval 能力矩阵)是 TODO 而非反驳。

## 四、收敛后的 Sprint 2 范围

可信证据闭环,明确不做:九类规则铺开、Jev 裁决权、评分卡权重。

1. 审计器自身威胁模型(目标控制哪些字节 → 如何流入 PoC → 重放器拥有什么权限)
2. PoC 合约先于规则数量:目标清单 + setup + action + 宿主 oracle + 负对照 +
   能力声明 + 超时 + 清理 + 预期不变量
3. 3 条确定性规则:AGI-02 参数无关审批记忆(FCODE-02)/ AGI-02 越权执行
   (FCODE-06)/ AGI-07 控制台写保护(FCODE-01)
4. 重放器即安全边界:无凭据、默认禁网、独立副本、文件系统限定
5. 盲测集 FCODE-04/07 + 负对照 + 变异样本
6. 三个对抗性回归:不引用金丝雀但诱导危险行为的目标文本 / 携带注入的结构化
   候选 / 自报 PASS 或篡改证据的 PoC
7. Jev shadow 上线(`triage_judge` 只读工具,只记录)

**验收标准**:在保留缺陷和负对照上,第三方仅依据审计包即可重放结论,并且
目标无法借 PoC 获得审计器权限。
