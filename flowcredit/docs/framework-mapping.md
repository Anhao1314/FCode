# 框架对照

"为什么不用现成的"这个问题，回答得好不好，取决于能不能说清**各自优化什么**。下面这张表的每一行都可以展开成一次讨论。

## 一张表

| 框架 | 优化目标 | 状态在哪 | 失败策略 | 谁决定结束 | 与本项目的关系 |
| --- | --- | --- | --- | --- | --- |
| **LangGraph** | 图式编排、人机协同 | 框架内部 checkpoint（格式由框架定） | 节点重试、可从任意 checkpoint 恢复 | 图走到 END | 编排更强；可证明性更弱 |
| **AutoGen** | 多智能体对话 | 会话历史 | 重新发消息 | 对话终止条件 | 目标是"多角色协作"，不是"单任务可审计" |
| **CrewAI** | 角色化团队、任务委派 | 任务对象 | 重试 | 任务完成 | 抽象层次更高，审计粒度更粗 |
| **OpenAI Agents SDK** | 厂商 SDK、handoff、tracing | 会话 + trace | 内置重试 | agent 返回 | tracing 是日志，不是防篡改证据 |
| **OpenAI Codex CLI** | 本地编码代理：沙箱 + 审批 + 执行策略 | rollout JSONL + SQLite 索引 | 沙箱拒绝后可升级重试 | agent 返回 / 沙箱判定 | 工具与协议可借；状态未哈希，失败语义与 FCode 相反 |
| **Temporal** | 通用持久执行 | 事件历史（强） | 确定性重放 | workflow 返回 | **最接近的工程同类**，但没有模型调用语义 |
| **Inspect（UK AISI）** | 模型能力评测 | eval log | 单样本失败 | scorer 判定 | 评"模型多强"，不是"该不该用模型" |
| **本项目** | 单任务的可证明执行 | sqlite 事件哈希链，可脱离代码验证 | unknown 不重试，只能对账 | Runtime 独立重算 | — |

## 三条实质差异

> Codex 的工具/审批/沙箱细节与融合方案见 [`codex-integration.md`](codex-integration.md)。

### 一、状态的**可验证性**，不是持久性

LangGraph 和 Temporal 都能持久化，而且做得比这里好得多。区别在于：它们的状态**只能由框架自己读**，格式是内部约定。这里的状态是一条公开的哈希链，任何语言、任何工具都能用 `sha256` 重算——`viewer/index.html` 就是这么做的，它不 import 任何 Python。

这意味着审计方不需要信任你的代码，只需要信任 SHA-256。

### 二、失败策略是**故意更差**的

所有列出的框架都会重试，因为重试能提高成功率。这里不重试，因为重试在"不知道有没有扣费"的场景下是**重复付费**。

这是一个明确的取舍：**可用性换正确性**。代价是 `unknown` 需要人工对账；收益是账目永远不会因为自动重试而失真。

如果场景允许重试（比如内部批处理、不计费的本地模型），这个设计就是过度保守的。

### 三、终止判定权在 Runtime，不在模型

多数框架里，agent 说"我做完了"就完了。这里 `succeeded` 只有一个入口：`Harness.verify()` 用确定性算术重算一遍，和模型给出的数字逐个比对。

模型可以提议 `report_blocked`，但 Runtime 还要复核世界是不是真的无解——如果还能算，就不许停。

## 什么时候该用它们

| 场景 | 建议 |
| --- | --- |
| 快速做一个能跑的原型 | LangGraph / CrewAI，别自己写 |
| 需要复杂的多角色协作 | AutoGen |
| 长流程、要断点续跑、但不涉及计费 | Temporal |
| 要评"这个模型行不行" | Inspect |
| 要回答"这次调用到底发没发出去、扣没扣钱" | 自己写，或者把这里的 core 抄走 |

## 如果要用框架，能借什么

- **Temporal 的确定性重放**：本项目的 `restore()` 只重放观测，不做完整的工作流重放。规模上去之后需要更严格的重放语义。
- **LangGraph 的图结构**：当前是固定优先级的线性循环。真正的分支（并行读多个来源、失败后换路径）需要图，而不是 if-else。
- **Inspect 的 scorer 抽象**：当前评分逻辑写死在 `verify()` 里，换任务就要改代码。

这三条都是 v3 的候选，不是现在的问题。
