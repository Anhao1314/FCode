# fixtures — 已知缺陷靶子

审计引擎的 ground truth 在这里:每个靶子是一组**已确认、带证据指针**的缺陷,
规则引擎的最小验收标准是"能独立找出这些缺陷,且每条发现可一条命令重放"。

## fcode-self/

FCode 自身经 2026-10-30 全面评估确认的 7 个问题(`known-issues.json`)。
用自己当第一个靶子是刻意的:一个挖掘 agent 应用缺陷的工具,先把自己挖开。

## synthetic/(Sprint 2)

人造漏洞靶,每个对应一条规则。生成原则:最小可复现,一个靶子只含一个缺陷,
让规则的判定契约可以精确对齐。

## 靶子纪律

- 靶子里的缺陷是**预置且声明的**——靶子文件头部注明缺陷位置与分类号,与
  Runtime 基准中"预置错误交付"同一纪律:失败保留在分母里,不藏。
- 靶子不是攻击武器库:PoC 以"证明缺陷存在"为限,不提供武器化增强。
